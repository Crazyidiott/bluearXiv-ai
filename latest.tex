\arxivwithtarget{2608.20341}{SDAD: Spec-Driven Agentic Development for the AI-Native SDLC}{Vu Hung Nguyen, Thanh Nguyen}\textbf{cs.AI}, cs.SE.

本文提出Spec-Driven Agentic Development (SDAD), 旨在解决LLM驱动的coding agents在超大context window下因规范模糊而导致的交付不可靠问题: 传统Agile的隐式知识传递无法支撑agentic synthesis的高速度, 而完全Waterfall又牺牲迭代效率. 方法将SDL C前移为intent capture、machine-readable specification、agentic synthesis与独立multi-agent verification, 并以human sign-off作为release authority的最终门禁. 为量化治理, 引入Ambiguity Tax与Spec Fidelity衡量spec质量, SER及$TCI_{agentic} = f(\rho, \phi)$(其中$\phi$为repair multiplier) 控制修复成本与可靠性边界. 实验与工业证据表明, 该框架将工程纪律从implementation阶段重定位至specification精度与可审计provenance, 使agentic速度与可靠验证可兼得.


\arxivwithtarget{2608.20342}{PrimeAgentOrchestrator: Memory-Primed Agent Spawning for Personal AI Infrastructure}{Myron Koch}\textbf{cs.AI}, cs.MA.

PrimeAgentOrchestrator (PAO) 针对 LLM coding agents 每次会话从空上下文启动、丢失历史知识的问题, 设计了一个记忆预注入的 agent spawning 系统. 该系统在生成新的 Claude Code 实例时, 并行查询 PostgreSQL 实体关系库和 Cloudflare Worker 语义索引, 通过后端特定的 retrieval 策略融合结果, 并利用配置自动读取机制将简报写入文件系统, 实现上下文预热. PAO 还覆盖了信任预置、就绪检测和自适应终端注入等完整 agent lifecycle 管理. 基于 2025 年 12 月至 2026 年 3 月的四个月部署经验, 作者总结了三代上下文交付机制的演进及其失败模式, 论证了在异构 memory 系统间做桥接而非统一构建的工程取舍.
